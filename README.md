# Weather History

A small web app to explore the recent **weather** and **air-quality** history of any place on Earth.

Type a city, pick a time range, and get interactive charts that show what the weather and the air were really like — no sign-up, no API key, no setup. Works on phones, tablets and desktops, in light and dark themes.

## What it shows

For any location you choose:

- **Summary tiles**: average temperature and humidity with their low/high, the **peak AQI** with its category and the EPA's health advice, and how much of the period has AQI data.
- **Three aligned chart cards** — temperature, relative humidity and US AQI — each on its own axis and sharing the same time axis:
  - the max and min of each series are labeled;
  - daily views show the **low–high range as a band** with the mean line on top;
  - the AQI card draws the official EPA color bands (Good → Hazardous) behind the line.
- Hovering (or tapping) one chart shows the same moment in all three; zooming one zooms them all.
- Weekends are gently shaded and day boundaries are marked on hourly views.
- Every chart has a **Table** view with the exact numbers.

## What you can do

- **Search any city in the world** with suggestions as you type, or use **📍 my location**.
- **Recent places**: focus the location box to jump back to your last five places.
- **Pick a time range** with one tap — 24h, 3d, 7d *(default)*, 2w, 30d, 3m, 6m, 1y — or a **custom date range** of up to 366 days. Ranges over 30 days switch to a daily view.
- **Switch units** between °C and °F.
- **Choose a theme**: 🖥 System (follows your OS), ☀ Light, or 🌙 Dark.
- **Share** the current view as a link (copied to the clipboard, or the native share sheet on phones).
- **Download** the data as CSV, or any chart as a PNG.
- **Vietnamese or English**: the site is in Vietnamese by default; the EN/VI button switches the whole page (numbers and dates too) without reloading.
- **City pages**: 87 places have their own address, e.g. [`/hanoi/`](https://tnam0x.github.io/weahist/hanoi/) or [`/tokyo/`](https://tnam0x.github.io/weahist/tokyo/) — all 34 provinces of Vietnam (after the 2025 merger), popular destinations and big world cities. Picking one moves the address there; any other place uses `/?location=…`. Back/forward work as expected.
- **Works offline**: after one visit the app is cached (installable as a PWA); without a network it shows the last data you loaded.
- **Your settings are remembered** — location, range, units, theme and language are restored next time. Links accept `?location=…&range=…` (or `&start=YYYY-MM-DD&end=YYYY-MM-DD`), `&units=f` and `&theme=dark`.

## Where the data comes from

All data is provided by [Open-Meteo](https://open-meteo.com/), a free open-source weather service that aggregates atmospheric model output (CAMS for air quality, ECMWF/IFS for weather) without requiring an API key.

- Weather: hourly or daily values back to 1940 (ERA5 archive). The archive lags a few days, so the
  last 3 days come from Open-Meteo's forecast endpoint and the charts reach the current hour.
- Air quality: typically the last ~2–3 years. If part of your selected range has no AQI data, the chart still shows the weather and the summary tells you the coverage percentage.

## Notes

- Times shown on the chart are in the **local timezone of the selected location**, not your browser's timezone.
- Air-quality numbers use the **US EPA AQI standard** (0–500, six categories). It's a close proxy for most national indices.
- If a request takes more than 30 seconds it is cancelled and a clear error is shown at the top of the page.
- Visits are counted with [GoatCounter](https://www.goatcounter.com/) (no cookies, no personal data).

## Hosting

The frontend lives in [`web/`](web/) and is **pure static** — HTML, CSS, and a few small ES module JS files. The browser talks to Open-Meteo directly (no backend needed), so it can be hosted anywhere that serves static files.
The public address `https://tnam0x.github.io/weahist/` is written into `SITE_URL` in
[`scripts/build_site.py`](scripts/build_site.py) and [`web/app.js`](web/app.js) (canonical URLs,
sitemap, share previews) — change both when hosting it elsewhere.

### Local development

The app itself needs no build. Serve `web/` with any static file server:

```bash
python -m http.server -d web 8000                   # open http://127.0.0.1:8000
python -m http.server -d web 8000 --bind 0.0.0.0    # same, reachable from your phone on the LAN
```

This serves only the home page: picking a city still works, but city addresses such as `/hanoi/`
don't exist until you build the site (below).

### Building the site

The deployed site is `web/` plus one static page per city, generated by
[`scripts/build_site.py`](scripts/build_site.py) (standard library only):

```bash
python scripts/build_site.py --out _site --base-path /   # local preview at the server root
python -m http.server -d _site 8000
```

`--base-path` is the URL path the site is served under; it defaults to `/weahist/` (GitHub Pages),
which is what CI uses.

It writes `/<slug>/index.html` for every place in [`web/cities.json`](web/cities.json) (own title,
description, canonical URL, structured data and crawlable text), a footer index of all cities, a
full `sitemap.xml`, a `404.html` that turns unknown paths into a search, and versions the service
worker's caches. (Python's `http.server` doesn't serve `404.html`; GitHub Pages does.)

To add or change city pages, edit [`scripts/cities_source.json`](scripts/cities_source.json) and run:

```bash
uv run python scripts/update_cities.py       # geocodes the list into web/cities.json
```

### Tests

The app is covered by browser tests in [`tests/e2e/`](tests/e2e/) (pytest-playwright, Chromium).
They build the site, serve it statically and mock every Open-Meteo call, so they need no network
after the first run (the pinned Plotly bundle is cached under `.cache/e2e/`).

```bash
uv sync                               # test tooling only — the app has no Python code
uv run playwright install chromium    # once
uv run pytest                         # everything
uv run pytest --headed -k filters     # watch some of them run
```

The suite checks behaviour (search, ranges, units, themes, languages, city URLs and history
navigation, saved prefs, shareable URLs, caching, offline use, error/timeout handling), layout on
phone, tablet and desktop viewports, design tokens and contrast, and SEO metadata for every page.

GitHub Actions runs lint and the full suite on every push and pull request; `main` is
built and deployed to GitHub Pages only when the tests pass.
